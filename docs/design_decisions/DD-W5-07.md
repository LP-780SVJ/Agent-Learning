## Context

Day1-Day6 provide Lead planning models, a validated Task DAG, Scheduler, Mailbox,
Worker lifecycle and SQLite process persistence. They do not yet provide one
coding-runtime adapter that assigns nodes to existing `CodingAgentRuntime`, waits
for bounded concurrent work, publishes results durably and returns the same result
contract consumed by `AgentEvalRunner`.

## Decision

1. `TeamCodingRuntime` implements the existing structural `CodingRuntime` contract.
   `WorkerExecutor` adapts one `WorkerAssignment + TaskClaim` into a revalidated
   bounded child `CodingAgentRunRequest`; it does not copy the Agent Loop.
2. `DurableTeamRuntime` remains the control-plane authority. Worker threads return
   values only. One coordinator thread performs schedule, claim, start, result
   publish, complete/fail and message ACK.
3. A bounded `ThreadPoolExecutor` matches the current synchronous Runtime API.
   `max_workers` is explicit. Week5 rejects concurrent nodes that may write one
   shared worktree.
4. Worker results publish in this order: atomic node artifact, durable Mailbox
   message, claim, artifact/fence validation, durable budget progress, Scheduler
   transition, ACK. The fence is `runtime_id + generation + attempt`.
5. Team-specific detail lives in `TeamRunArtifact`; the common
   `CodingAgentRunResult` carries public task outcome and neutral artifact refs.
6. The Lead proposes relative weights 1..5. Runtime reserves 20 percent, applies
   minimum/maximum constraints and owns absolute node/global ledgers. Invalid
   weights fall back to equal allocation.
7. V1 registers local GENERAL, BACKEND and TEST Workers. Required capabilities are
   a hard subset gate; exact role wins; compatible GENERAL is the only fallback.
8. `team_progress.json` atomically retains allocation and hash-bearing node refs.
   Resume replays usage from verified artifacts. An old attempt with unknown usage
   conservatively exhausts its node allocation and cannot receive a free retry.
9. Team DAG completion is not final code success. The unchanged `AgentGrader`
   remains the authority for visible checks, regression, hidden acceptance,
   security and budget.
10. Real LLM smoke is fixed to B01, one backend Worker and one deterministic node.
    It proves wiring only, not multi-Agent improvement.
11. Worker `changed_files`, `diff` and verification are untrusted claims. The
    coordinator derives changed files and a safe text diff from the final Git
    workspace. Verification remains empty until a coordinator-owned verifier or
    external `AgentGrader` supplies trusted evidence.
12. Durable Worker errors, Mailbox payloads, events and Team artifacts pass through
    a shared recursive redaction boundary. Artifact writes sanitize again as
    defense in depth; unexpected errors retain a category, exception type and safe
    summary hash instead of unchecked `str(exception)`.
13. The smoke manifest is an atomically replaced state machine: `NOT_RUN` for dry
    run, `STARTED` during a real attempt, then `COMPLETED` or `FAILED` with terminal
    metadata. An exception is recorded as a redacted failure and then re-raised.
14. The Team run artifact schema is version 2 because trusted workspace evidence
    and explicit `worker_reported_*` provenance change the durable contract. Old
    schema-1 B01 evidence is retained unchanged rather than silently reinterpreted.
15. A child Runtime id is a path-bearing infrastructure identifier, not a display
    label. WorkerExecutor generates a legal readable prefix plus a hash of parent,
    node and attempt, satisfying the shared Worktree/Checkpoint contract without
    normalization collisions.
16. Native tool schemas have one exact authority: `ModelRequest.tools`. The system
    message carries only a compact catalog and protocol examples. Text-only mode
    embeds the full schema in messages and leaves `ModelRequest.tools` empty.
17. Initial-context reuse is not a permanent no-progress exemption. Same-turn safe
    batches complete, while two cross-turn all-cached batches stop deterministically;
    a successful patch changes workspace version and permits fresh reads.
18. General evidence redaction preserves ordinary source identifiers and domain
    language. Unexpected exception persistence uses a stricter fail-closed rule.
    Terminal Team failure classification retains budget, provider, environment and
    protocol roots when a Worker already supplied them.
19. Structured compaction retains a bounded, prioritized working set of exact
    read/search observations. Cache novelty is request-relative: replay restores
    compacted evidence without advancing the visible-duplicate stall counter, while
    already-visible repetition receives one explicit advisory before termination.
20. One model turn may contain at most four list/read/search calls. Excess calls
    receive correlated rejection results instead of silently consuming exploration.
    Every provider request emits content-free request evidence for context-budget
    diagnosis without duplicating prompts or secrets.

## Alternatives

| Option | Benefit | Why not selected |
| --- | --- | --- |
| Copy a Team-specific Agent Loop | Direct customization | Duplicates safety, verification and recovery semantics |
| Put Scheduler inside `CodingAgentRuntime` | One object | Couples single-Agent execution to Team-only state |
| Async rewrite | High concurrency ceiling | Existing provider/runtime protocol is synchronous; larger unproven change |
| Unbounded thread submission | Small implementation | Violates resource and budget control |
| Shared writable worktree | Easy multi-Worker demo | Races patches and destroys ownership/audit boundaries |
| Team fields in common result | One JSON object | Pollutes Single/Reviewer runtimes with irrelevant optional fields |
| Runtime adapter + separate artifact | Reuse and neutral common result | Selected |

## Consequences

The Team control plane is deterministic and auditable while existing coding and
grading behavior remains reusable. SQLite commits and atomic artifact files are
two stores, so crash windows still require reconciliation. Progress is written
before a terminal Scheduler transition; this may conservatively charge an attempt
that did not commit, but it never resets budget after a crash.

Fencing rejects stale control-plane results. It does not stop an old thread/process
or guarantee exactly-once Git, command, file or network effects. A crash with
unknown Worker usage fails closed. Per-Worker worktrees, patch integration and
conflict policy remain Week6 work.

The learner ran three manual B01 attempts. The first emitted two sound replacement
edits, both rejected because `B01:node-worker-implementation:attempt-1` violated

The latest deterministic regression recreates the third run's low-budget shape:
two four-call exploration turns must leave API, service, exceptions and token
observations simultaneously visible on request three, after which the same
production chain applies a patch, runs task/regression verification, checks the
diff and completes. Provider-request metadata is also persisted separately for
future token/visibility diagnosis. The model and Docker outcome remain scripted,
so this is causal regression evidence rather than a real-LLM score.

## Remaining Limits

- No per-Worker worktree, patch merge, reviewer gate or conflict resolution.
- No real multi-Worker coding experiment.
- No external side-effect exactly-once guarantee.
- No distributed Workers, remote queue or multi-primary Runtime.
- No performance conclusion before weekend raw samples.
- B01 is one dev task, not a held-out Team coding benchmark.
- The failed B01 sample does not establish that the Team architecture is invalid;
  it establishes that this stochastic one-Worker attempt did not pass.

## Post-fix Real Provider Evidence

Later real runs exposed three control-plane gaps after the bounded working set was
added: compaction dropped the assistant intent and duplicate advisory; a successful
patch left stale pre-edit intent visible; and task/regression completion was exposed
as one coarse next action. The Runtime now preserves deterministic control state,
uses a conservative token estimate, and advances verification by missing command.

The final B01 run at
`evals/week5/agent_runs/day7-b01-team-smoke-completion-settlement-20260903_141033`
completed with one trusted source change, task verification, regression, hidden
acceptance and security all passing. Completion used
`runtime_completion_gate_settlement`: after the model inspected the final diff, a
redundant optional action could no longer override a ready trusted gate. This is a
single dev smoke result, not a Team benchmark or ablation conclusion.
