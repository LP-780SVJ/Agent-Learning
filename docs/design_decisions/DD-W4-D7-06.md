# DD-W4-D7-06: Docker-Visible Worktrees and Pre-Provider Preflight

## Status

Accepted on 2026-08-27.

## Context

Two B01 stability runs produced correct source patches and passed the public,
regression, and hidden Grader commands. The production Runtime still failed its
own verification because the worktree lived below `/Users/root`, while the
active Colima VM shared the `sqlee` home directory. The host could read the
path, but Docker reported that the bind source did not exist.

One run returned the direct mount error. The other retried a semantically
equivalent test command and stopped as `repeated_action`. Both were evaluation
false negatives caused by an execution-environment mismatch.

## Decision

- Resolve one worktree base with this precedence: CLI `--worktree-root`,
  `CODETEAM_WORKTREE_ROOT`, then `~/.codeteam/worktrees`.
- Namespace product worktrees by canonical repository-path hash and evaluation
  worktrees by run id. Keep result artifacts under `--output`; do not require
  that directory to be mountable by Docker.
- Before context construction or the first Provider request, run a hardened,
  read-only container probe against the actual worktree mount.
- Classify missing Docker CLI, inaccessible daemon, absent image, invisible
  bind source, and generic container startup failures separately.
- Return `PAUSED + sandbox_unavailable` with zero model usage when preflight
  fails. Never fall back to host execution.
- Treat Docker exit code 125 and mount-startup diagnostics as Sandbox backend
  failures. Halt the Agent loop immediately after recording the tool result.
- Keep trusted Grader subprocesses independent, but require Runtime completion;
  post-run acceptance cannot upgrade a paused actor to success.
- Count every patch tool invocation, including rejected input. Keep code-repair
  attempts as a separate metric. Prefer compact exact replacements that are
  converted locally to a diff and still pass through the safe Patch Lane.

## Consequences

- Colima-compatible worktrees no longer depend on the repository's physical
  location.
- Environment failures are detected before Provider cost and reported
  separately from provider, protocol, coding, and verification failures.
- Existing Sessions retain their recorded worktree paths and may pause during
  resume if that legacy path is not Docker-visible.
- The preflight does not guarantee that Docker remains available for the whole
  task, so runtime Sandbox failures retain the same terminal pause behavior.

## Verification

- Unit tests cover worktree-root precedence, repository collision resistance,
  Eval run isolation, cleanup ownership, and CLI propagation.
- Sandbox tests cover successful probes and CLI, daemon, image, and mount
  failures.
- Runtime tests prove zero Provider calls on preflight failure and immediate
  pause on an in-loop Docker mount failure.
- Evaluation tests prove an environment-blocked actor remains unsuccessful even
  when independent Grader evidence exists.
