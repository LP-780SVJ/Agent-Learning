# DD-W4-D7-03: One Coding Agent Runtime for Product and Evaluation

## Status

Accepted on 2026-08-25.

## Decision

`codeteam run` and `codeteam agent-eval` must invoke the same
`CodingAgentRuntime`. Evaluation may prepare fixtures, create task worktrees,
run pristine-oracle checks, and grade final state, but it may not own a second
patch-generation or repair loop.

The Runtime uses a provider-neutral JSON action protocol and exposes only
bounded repository tools plus the `SafeExecutionService` patch and command
lanes. A task is completed only when final Git state contains a real diff, a
visible verification has passed, and final changed paths satisfy the safety
gate.

Provider response dialects are normalized at the Agent protocol boundary as
specified by `DD-W4-D7-04`; exact raw responses remain part of the durable and
evaluation evidence.

Hidden acceptance commands are never included in Runtime requests, messages,
tool observations, or repair feedback. They run once after the Runtime stops.

## Consequences

- Product and benchmark behavior cannot drift through separate actors.
- Worktree, tool, repair, token, timing, and failure evidence describe the
  production loop being evaluated.
- Docker unavailability and approval requirements pause fail-closed.
- Legacy `PatchActor` and `LLMPatchGenerator` remain compatibility code only.
- The current 11 tasks are a development suite, not held-out evidence.
