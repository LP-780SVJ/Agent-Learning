# DD-W4-D7-10: Versioned Runtime-owned Completion

## Status

Accepted, 2026-08-29.

## Context

In the same historical run B02, F01, and R03 had the intended diff and passed
task, regression, hidden, and security checks, yet the actor ended as
`repeated_action`. The model had no native terminal handshake: it kept calling
tools after objective completion and Runtime only validated a textual
`completed` claim after the loop had already stopped.

## Decision

Every verification record carries `workspace_version`; diff review is
`git_diff_checked_version`, never a timeless boolean. `CompletionGate` is a
small pure policy that requires a real safe diff, all task commands, every
configured broad regression command, current-version evidence, current-version
diff review, clean workspace hygiene, and no execution pause. Hidden acceptance
is intentionally absent.

Runtime registers provider-neutral native tool `submit_result(summary, notes?)`.
The model requests completion; only `CompletionGate` authorizes it. The call
must be the sole call in the assistant turn. Rejected and accepted calls both
receive a correlated `role=tool` result. Acceptance persists that result and
then returns a typed completed loop outcome without another Provider turn.
Mixed batches fail closed without partial execution. Textual final output
remains a compatibility fallback but is checked by the same gate.

Ready-state duplicate calls are skipped with a correlated advisory telling the
model to call `submit_result`; bounded no-progress protection remains. Readiness
does not itself terminate the actor. Durable Session state stores evidence
history, fingerprint, workspace version, hygiene, and diff-review version. A
missing/old fingerprint or resume drift advances the version and makes prior
evidence stale; no trusted `ready` boolean is persisted.

## Alternatives rejected

- Trust model fields such as `tests_passed`: self-attestation is not evidence.
- Auto-complete as soon as the gate is ready: removes the explicit Agent turn
  boundary and can terminate while the model still intends a valid edit.
- Keep clearing verification after patches: loses audit history and makes
  resume analysis impossible.
- Let the external Grader rescue the actor: conflates actor correctness with
  post-run oracle results.

## Consequences

Completion is version-aware, auditable, native-tool compatible, and owned by
Runtime. Evaluation can distinguish actor completion, completion-ready false
negatives, post-ready calls, and verification workspace mutations. R02 remains
a genuine semantic coding miss and is deliberately unchanged.
