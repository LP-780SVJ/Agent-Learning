# DD-W4-D6-02: Ctrl+C, Exit Code, and Output Contract

- **日期**: 2026-08-22
- **模块**: `codeteam/cli/app.py`, `codeteam/cli/render.py`, `codeteam/agent/orchestrator.py`, `codeteam/session/service.py`
- **状态**: Accepted（MVP 约定完成）
- **Evidence status**: PROPOSED（真实 SIGINT E2E 与 JSONL stream 输出验证后再升级）

---

## Problem

Coding Agent CLI 面向人类开发者，也面向脚本和 CI。用户需要知道命令是否成功、是否失败、是否只是被自己中断并可恢复。

如果所有错误都 exit 1、所有信息都写 stdout、Ctrl+C 直接变 FAILED，CLI 就无法成为可靠产品接口。

## Context

Day4 已实现 Session Persistence + Resume。Day6 把 Runtime 暴露到 CLI，因此中断、恢复、错误输出和 exit code 必须成为稳定契约。

`Ctrl+C` 不是普通失败。它表示用户主动暂停长任务，正确语义应是：

```text
KeyboardInterrupt
  -> stop active operation
  -> persist PAUSED session
  -> print resume instruction
  -> exit 130
```

## Requirements

1. Ctrl+C 应落盘为 PAUSED，而不是 FAILED。
2. Exit code 应克制并稳定：
   - `0`: 成功或可接受的 read-only 空结果。
   - `1`: Runtime 执行失败。
   - `2`: 用户输入、状态、ownership、schema、session 等请求不合法。
   - `130`: 用户中断。
3. stdout/stderr 必须分离。
4. Human output 与未来 JSON/JSONL output 要有边界。
5. Non-TTY 环境不能弹出无法完成的 prompt。
6. 错误不能直接把 Python traceback 暴露给用户。

## Alternatives

### Option A: Everything exits 1

- **优点**: 实现简单。
- **缺点**: 脚本无法区分用户输错、任务失败、主动中断；CI 无法做细粒度处理。

### Option B: Print all messages to stdout

- **优点**: 方便肉眼看。
- **缺点**: JSON/patch/stdout 被错误文本污染；脚本无法安全解析。

### Option C: Ctrl+C as FAILED

- **优点**: 状态机简单。
- **缺点**: 把用户暂停误记为任务失败；Resume 语义被破坏；failure analysis 失真。

### Option D: Explicit Exit and Output Contract（选定）

- **优点**: 人类和脚本都可依赖；暂停与失败分离；stdout 可承载 patch/json，stderr 承载错误。
- **缺点**: 需要每个命令明确映射 domain result -> exit code。

## Decision

采用稳定的 CLI contract：

```text
0   success
1   runtime failure
2   invalid request / invalid state / ownership violation
130 user interrupt
```

`render_error()` 写 stderr。正常 human/json 输出写 stdout。当前 MVP 不做交互式 picker；无法确定 session 时 fail closed，而不是偷偷创建或弹不可完成 prompt。

## Why

1. **Resume 语义正确**：Ctrl+C 是暂停，不是失败。
2. **脚本友好**：CI 和外部工具可根据 exit code 判断下一步。
3. **输出可解析**：JSON/patch 不被错误文本污染。
4. **安全**：invalid ownership / session / checkpoint 以 exit 2 拒绝，不进入 mutation backend。

## Consequences

- 每个命令都必须显式处理 domain errors。
- `diff` 的错误必须走 stderr，成功 stdout 才可被当作 review artifact。
- `rollback` 的非法请求 exit 2；执行后失败 exit 1。
- `resume --provider/--model` 在 registry factory 未接线前必须 fail closed，不能假装 override 成功。

## When to Revisit

- 引入 JSONL streaming 后，需要定义 event stream 的 stdout/stderr 边界。
- 真正跨进程 SIGINT E2E 稳定后，将 Evidence 从 PROPOSED 升级。
- 如果增加 session picker，必须显式区分 TTY 与 non-TTY；non-TTY 不得阻塞等待交互。
