# DD-W4-D7-04: Provider Dialect Firewall and Bounded Protocol Repair

## Status

Accepted on 2026-08-25.

## Context

The first real-model run of the unified Runtime reached the provider without
network failures, but all 11 tasks stopped before tool execution. Ten responses
used DeepSeek DSML tool tags and one used a Markdown JSON fence. The Runtime
accepted only a bare JSON object and also required model-generated `call_id`
values that were not described in the prompt.

This was a transport-compatible but protocol-incompatible integration: an
OpenAI-compatible HTTP endpoint does not guarantee one canonical response
dialect.

## Decision

Introduce `codeteam.agent.protocol` as a dialect firewall between raw model
text and the provider-neutral Agent Loop.

- Preserve the exact assistant response in message history and evaluation
  artifacts before normalization.
- Normalize one unambiguous bare JSON object, one complete Markdown JSON fence,
  or one structurally validated DeepSeek DSML tool envelope.
- Treat DSML parameter bodies as opaque data while validating the surrounding
  structure, so source code containing `<` or `&` is not corrupted.
- Reject multiple envelopes, trailing action text, malformed tags, duplicate
  parameters, and invalid typed values fail-closed.
- Ignore provider-supplied infrastructure IDs. The Runtime assigns
  `step-<n>-call-<m>` after schema validation, which guarantees local uniqueness
  and stable tool-observation correlation.
- Allow at most two protocol-repair turns. Feedback contains only the parsing
  error and canonical schemas; it does not echo secrets, hidden acceptance, or
  additional repository material.
- Count protocol repair separately from code repair and persist its budget
  across Session resume.

The Agent Loop continues to depend only on `llm.base` for model transport. The
dialect firewall belongs to the Agent protocol boundary, not to a concrete HTTP
client or provider registry.

## Consequences

- Product `run` and `agent-eval` accept the real response shapes observed in the
  baseline without making provider syntax part of tool implementations.
- Raw evidence remains auditable; normalization never rewrites the saved model
  response.
- Prompt-only reliability is not treated as a correctness boundary.
- Protocol failures become measurable through repair-attempt and exhausted
  failure counts.
- New provider dialects require an explicit decoder and adversarial tests; the
  Runtime does not heuristically execute arbitrary text.

## Verification

- Unit tests cover bare JSON, fenced JSON, DSML multi-call/type decoding,
  source code containing XML characters, malformed tags, and ambiguous mixed
  envelopes.
- Agent Loop tests cover Runtime-owned IDs, successful protocol repair, the
  two-attempt cap, and disabling repair.
- Runtime integration completes a DSML action sequence followed by a fenced
  final output.
- All 11 raw first responses from the failed baseline normalize offline: ten
  DSML responses and one Markdown JSON response, containing 21 tool calls.
