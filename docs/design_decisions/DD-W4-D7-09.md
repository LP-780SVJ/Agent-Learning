# DD-W4-D7-09: Verification Scratch Isolation

## Status

Accepted, 2026-08-29.

## Context

The historical 11-task run `verification_contract_11task_20260829_134620`
showed F03 writing pytest `tmp_path` data below `/workspace/pytest-of-root`.
The resulting files and `current` symlinks were real source-workspace changes.
`CheckpointManager` correctly refused to snapshot those symlinks, so every later
patch failed closed. The defect was verification scratch ownership, not the
checkpoint safety rule.

## Decision

Agent-visible verification mounts `/workspace` read-only. Docker provides a
bounded 128 MiB `/tmp` tmpfs with `nosuid,nodev,noexec`, and Runtime fixes
`TMPDIR`, `TMP`, `TEMP`, `HOME`, `XDG_CACHE_HOME`, and
`PYTHONPYCACHEPREFIX` below `/tmp`. Runtime also fixes
`PYTEST_ADDOPTS=-p no:cacheprovider` so pytest does not create repository cache
state. The model controls none of these values.

Before and after every `run_tests`, Runtime fingerprints all tracked and
non-ignored untracked Git paths by type, mode, and content. Symlink targets are
hashed as link metadata and never followed. A mutation increments
`workspace_version`, records `workspace_hygiene_failed` evidence at the new
version, invalidates diff review, pauses execution, and is never auto-deleted.
Patch application remains the host-side `SafeExecutionService` lane.

## Alternatives rejected

- Auto-delete verification output: hides evidence and risks deleting model or
  user work.
- Weaken `CheckpointManager` symlink rejection: converts a correct security
  boundary into a traversal risk.
- Writable host scratch bind mount: adds another host path and cleanup/security
  lifecycle.
- Writable source workspace with conventions: pytest and third-party tools do
  not reliably honor conventions.

Docker tmpfs is the smallest explicit writable capability and dies with the
container.

## Consequences

Verification code can use `tempfile` and pytest `tmp_path`, but attempts to
write source fail at the mount. The fingerprint remains a defense-in-depth
detector for runner doubles, Docker/config drift, and tools that mutate through
unexpected paths. Hygiene failure is observable and completion-blocking.
