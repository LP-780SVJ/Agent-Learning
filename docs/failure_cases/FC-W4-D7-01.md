# FC-W4-D7-01: Correct Patch, Missing Docker Pytest, Repeated Action

Date recorded: 2026-08-29
Status: Mitigated offline; pending user-run B01 validation

## Trigger

A user-run B01 generated and safely applied the correct refresh-token patch,
then executed the Runtime-required command:

```text
python -m pytest tests/task_verification/test_b01.py -q
```

## Failure Chain

```text
Correct patch generated and applied
↓
Runtime executes required python -m pytest
↓
Docker Python has no pytest module
↓
Agent attempts repository-recommended uv command
↓
Runtime exact verification allowlist rejects it
↓
Agent retries required command
↓
Repeated action
↓
Actor marked failed
↓
External trusted-host grader proves the patch is correct
```

## Root Cause

Runtime verification commands and the sandbox verification environment did not
share an explicit compatibility contract.

The Agent did not choose the wrong command. `REPEATED_ACTION` was not the root
cause; it was the final symptom after an infrastructure failure was repeatedly
fed back as if it were a code/test failure.

## Mitigation

- Preserve the Docker infrastructure preflight.
- Add a separate, fixed Python+pytest verification environment preflight.
- Own a digest/version-pinned minimal verification image in the repository.
- Fail with `verification_environment_failed` before Provider execution when
  Python/pytest is unavailable.
- Preserve exact task verification commands and SafeExecution routing.
- Classify `No module named pytest` during `run_tests` as environment drift,
  while ordinary pytest assertion failures remain repairable task feedback.

## Regression Evidence

- Fake Runtime/provider tests assert zero Provider calls, zero steps, zero tool
  calls, and zero repairs on preflight failure.
- Real Docker tests assert Python 3.11.15 and pytest 9.1.1 in the configured
  project image.
- Post-fix B01: `NOT_RUN_BY_CODER`, pending user validation.
- 11-task benchmark: `NOT_RUN`.
- Ablation: `NOT_RUN`.

## Remaining Risk

The contract currently covers only Python+pytest, not arbitrary repository
dependencies. Completion Ownership / `READY_TO_FINALIZE` is a separate pending
problem and was not changed by this mitigation.
