# FC-W4-D7-06: F04 Late Patch Under a Silent Run-level Cap

## Evidence

- Campaign: `evals/week4/agent_runs/stability_20260830_002409`
- Run: `09_11task_2_20260830_003505`
- Actor outcome: failed, `failure_category=max_steps`
- External outcome: acceptance, regression, task verification, security, and
  within-budget checks all passed
- Budget facts: task declared 30, EvalRunConfig run cap 20, effective 20
- Consumption: 20 model turns, 32 tool calls, 5 successful patches

## Timeline

Workspace version 4 passed task and broad regression verification. Turn 17 then
made a valid documentation patch, advancing to version 5 and correctly making
the version-4 verification stale. Turn 18 spent the shrinking budget on optional
ruff/mypy diagnostics, turn 19 reviewed the diff, and turn 20 submitted. Runtime
correctly rejected submission because version 5 lacked current verification;
the flat step budget then ended.

## Root cause

F04 declared a 30-step task budget but was silently capped by the run-level
20-step default. Within that fixed 20-step experiment, a late valid workspace
mutation correctly invalidated prior verification, while the flat budget
reserved no turns for current-version verification and finalization. This is a
finalization-budget / Actor orchestration false negative, not evidence that the
model could not implement the task.

## Resolution

The CLI and stability script now pass `--max-steps 20` explicitly and result,
summary, and manifest artifacts distinguish task-declared, run-cap, effective,
and source budgets. A deterministic reserve inside those same 20 turns tells the
model the exact missing current-version requirements and authoritative commands.
It may still apply a real patch; the gate is recomputed and new verification is
required. If the last legal action makes the gate READY, terminal settlement can
complete without a free model turn.

## Regression coverage

`tests/agent/test_coding_runtime.py` simulates pass at v1, late patch to v2,
remaining turns 3, re-verification, diff review, and boundary settlement.
`tests/evaluation/test_agent_eval_runner.py` parameterizes B02/B05/F04/R02/R03
declared budgets against effective 20. Real-provider validation remains pending
user run.
