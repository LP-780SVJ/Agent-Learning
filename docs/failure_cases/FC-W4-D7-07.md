# FC-W4-D7-07: F03 Native Batch Premature Stop

## Evidence

- Campaign: `evals/week4/agent_runs/stability_20260830_102307`
- F03 run: `02_F03_2_20260830_102401`
- Campaign outcome: Actor 39/40, security 40/40
- Targeted F03: 4/5; B01: 2/2; full 11-task repetitions: 33/33
- Failed Actor outcome: `failure_category=no_progress`, 11 turns, 33 tool
  calls, 0 patch attempts, 0 changed files, 31 diagnostic progress observations
- Provider/protocol/sandbox/verification environment: available, native tools,
  no protocol repair

## Timeline

The model had already read the dispatcher, public test, configuration, and
dependency evidence. It concluded that dispatch must stop only for an explicit
false flag and selected a small parser/fallback direction. Turn 10 listed the
repository and received a cached observation, leaving the legacy per-call
no-progress counter at one.

Turn 11 then declared one native batch:

```text
read_file("AGENTS.md")                    cached
read_file("src/experimental/broken_parser_case.py") fresh
read_file("src/plugins/loader.py")        fresh
```

The first call hit cache, raised `cached_no_progress_count` to two, and returned
`NO_PROGRESS` from inside the `for call in tool_calls` loop. The durable message
trace contains the ToolResult for `AGENTS.md`, but no ToolResult for the two
later provider/runtime call IDs.

## Root cause

> The stall detector operated at ToolCall granularity instead of native
> assistant-turn granularity.

Repeated non-destructive action used the same mid-loop return shape and carried
the same risk. This was Runtime-induced opportunity loss, not a Provider,
protocol, sandbox, completion, finalization, or ProgressPolicy failure.

## Resolution

The Runtime now aggregates cached/repeated/fresh outcomes across the complete
safe batch and applies the mechanical stall policy once per assistant turn.
Repeated exploration returns correlated cached/duplicate observations and
continues. Any uncached observation or successful patch makes the turn non-pure
mechanical; only a second complete stalled turn may stop. Safety, destructive
repeat, mixed completion, backend halt, and tool-budget rejection remain
fail-fast and explicitly account for rejected/unexecuted calls.

Structured `failure_origin` and batch metrics now propagate through Runtime,
Eval result/summary/manifest, and stability aggregation. Future stability runs
fail when a progress guard leaves safe calls unprocessed, while allowing a
legitimate complete mechanical-loop stop.

## Regression coverage

- `tests/agent/test_batch_aware_stall_detection.py`: exact F03 multi-tool native
  turn, cached/repeated mixes, two-turn guard, budget/halt rejection, origins.
- `tests/agent/test_coding_runtime.py`: cached read plus patch advances workspace
  and source progress; mixed completion and repeated verification remain safe.
- `tests/evaluation/test_agent_eval_runner.py`: result, summary, and manifest
  propagation.
- `tests/evaluation/test_stability.py`: premature-stop gates and F03 >=4/5 floor.

## Limitation

The dropped calls were fresh reads, not an `apply_patch`. This trace proves a
lost execution opportunity, not guaranteed counterfactual task success. F03 can
still fail occasionally for genuine model reasoning reasons.
