# CodeTeam 代码架构

本文档是持续维护的架构说明，记录当前代码如何分层、每层负责什么、哪些边界不能穿透。

## 当前定位

CodeTeam 是一个本地优先、provider-neutral 的 coding agent runtime 学习项目。它目前已经具备：

- Agent loop、工具调用、最终输出语义校验、事件和用量统计。
- 仓库扫描、符号索引、ImportGraph、检索排序、Repo Map、上下文压缩。
- Git patch/worktree/checkpoint/diff/rollback。
- CommandPolicy、Approval、SafeExecutor、Docker sandbox。
- Task/Plan/Repair/Failure Recovery。
- Durable Session、pause/resume、event log。
- CLI 产品入口：`run`、`resume`、`diff`、`rollback`、`inspect-repo`、`context`、`eval`。
- 统一 `CodingAgentRuntime`：主动检索、编辑、Docker 验证、diff 检查和局部 repair。
- Provider-neutral `ModelRequest → ModelTurn`：生产优先 native tool calling，
  bare JSON、Markdown JSON、DeepSeek DSML 与 bounded protocol repair 作为 fallback。
- 独立 Sandbox Infrastructure / Verification Environment Preflight：Provider
  前确认 Docker mount 与 Python+pytest toolchain，并保存镜像/版本证据。
- 检索 benchmark 和 11-task dev EvalRunner/Grader。

## 关键边界

### CLI 层

CLI 只负责参数解析、请求 DTO、错误渲染和退出码。它不应该直接实现仓库检索、session 恢复、Docker policy 或 patch 逻辑。

### Application / Service 层

这一层编排多个 domain 模块。例如 `build_context.py` 把 RepositoryIndex、QueryAnalyzer、CandidateGenerator、FileRanker、RepoMap、InstructionLoader 和 Compressor 串起来。

### Agent Orchestrator

`SingleAgentOrchestrator` 负责状态推进和依赖编排，不应该实现底层 Git、Docker、LLM HTTP 或文件解析细节。

### Agent Protocol 层

`codeteam.agent.protocol` 是 raw provider response 与内部 action schema 之间的 dialect firewall。它可以识别明确的 JSON、完整 Markdown JSON fence 和 DeepSeek DSML，但不能从任意自然语言中猜测动作。原始 assistant 输出必须先保存，再规范化；混合多个 envelope 或尾随 action 必须拒绝。

`call_id` 属于 Runtime 基础设施，不属于模型业务意图。Agent Loop 在 schema
校验后生成 `step-n-call-m`。native path 另存 opaque `provider_call_id`，只供
Provider adapter round-trip；ToolRegistry、ToolResult、events、重复动作判断和
SafeExecution 始终使用 Runtime ID。

### LLM / Provider Adapter 层

`codeteam.llm.base` 定义 provider-neutral `ModelRequest` 与 `ModelTurn`。
OpenAI/DeepSeek wire payload、native tool schema、finish reason、response ID、
capability negotiation 和 retry metadata 只存在于
`codeteam.llm.openai_compatible`。CLI 只读取配置并组装 client，不解析
`choices[0].message.tool_calls`。

### Git 层

Git 层负责 workspace 状态和可恢复性：

- PatchValidator 先校验再应用。
- GitWorkspace 失败时验证没有半截副作用。
- WorktreeManager 做任务级隔离。
- CheckpointManager 做快速恢复。

### Execution / Sandbox 层

执行链路必须保持：

```text
CommandRequest -> CommandPolicy -> Approval -> SafeExecutor -> SandboxRunner
```

Policy 判断意图，Sandbox 限制能力。两者不能互相替代。

### Session 层

`session.json` 是 resume source of truth；`events.jsonl` 是 audit/debug/evaluation history。Session 不持久化 runtime object，只保存可重建配置和 durable state。

### Evaluation 层

Evaluation 是外部 judge，不应相信 agent final message。正式 task success 必须由 hidden acceptance、regression、安全和预算共同决定。

- `codeteam run` 已接入统一 `CodingAgentRuntime`，真实 provider 与评测共用执行路径。

  Agent Turn 已离线闭环，真实 B01 smoke 为 `NOT_RUN_BY_CODER`，11-task
  benchmark 仍为 `NOT_RUN`。
- Full mypy 存在历史 import-chain/stub/type debt。

## 后续维护规则

- 新功能先明确所属层级，避免 CLI 或 orchestrator 吞掉底层职责。
- 新的安全能力必须同时说明 policy 边界和 sandbox 边界。
- 新的 agent 成功率必须来自外部 eval harness，不来自 agent 自我报告。
- 新 benchmark 必须保存 dataset、manifest、raw results 和 report。
- 大规模 lint/type cleanup 与功能修复分开提交，避免 review 噪声。

### 4. `codeteam run` 统一产品链路

`run` 是生产 Coding Agent 的唯一入口。它从请求时 HEAD 创建 linked worktree，主工作区不被修改；Runtime 结束后保留 worktree 和分支，不提交、不合并。

```text
CLI run(task, repo, provider/model, budgets)
  -> RunRequest
  -> run_agent_task(request)
  -> WorktreeManager.create(task_id, base_ref="HEAD")
  -> SessionService.create_session(..., WorktreeRef, real provider/model)
  -> CodingAgentRuntime.run(CodingAgentRunRequest)
       -> ContextApplicationService.execute(...)       # 仅启动上下文
       -> create_runtime_tools(...)                    # 七类工具
       -> normalize_verification_argv/cwd(...)         # 单一相对名字空间
       -> run_agent_loop(...)                          # provider-neutral action loop
       -> normalize_model_output(raw)                  # JSON / fence / DSML
       -> Runtime 分配 step-n-call-m
       -> model tool_calls
            -> list_files / read_file / search_code
            -> SafeExecutionService.execute_patch(...)
            -> SafeExecutionService.execute_command(...) -> Docker
            -> git_status / git_diff
       -> final completion gate
            real diff AND visible verification pass AND safe final paths
  -> persist Session runtime_state / usage / checkpoints / events
  -> COMPLETED(0) / FAILED(1) / request error(2) / PAUSED(130)
```

入口函数：

```python
run_agent_task(request: RunRequest) -> None

CodingAgentRuntime.run(
    request: CodingAgentRunRequest,
) -> CodingAgentRunResult
```

关键内部函数：

```python
_build_repository_ref(repo_root: Path) -> RepositoryRef
_git_output(repo_root: Path, *args: str) -> str
_session_store_for_repo(repo_root: Path) -> JsonSessionStore
_build_model_client(
    provider_id: str | None,
    model_id: str | None,
) -> tuple[str, str, ModelClient]
_exit_code_for_runtime_status(status: RuntimeStatus) -> int
```

Runtime 请求核心字段：

```python
CodingAgentRunRequest(
    task_id: str,
    task: str,
    workspace_root: Path,
    provider_id: str,
    model_id: str,
    context_budget: int = 4096,
    max_steps: int = 20,
    max_tool_calls: int = 40,
    max_repairs: int = 3,
    max_protocol_repairs: int = 2,
    compaction_mode: Literal["structured", "none", "naive"],
    verification_commands: tuple[tuple[str, ...], ...] = (),
    task_verification_commands: tuple[tuple[str, ...], ...] = (),
    initial_messages: tuple[Message, ...] = (),
    initial_protocol_repair_streak: int = 0,
)
```

边界：

- `run` 永远不执行 hidden acceptance；hidden 只属于 Grader。
- `run_tests` 必须通过 CommandPolicy 和 Docker，Docker 不可用时 fail-closed 并暂停。
- `run_tests.argv` 和 `cwd` 的内部形式必须相对 task workspace；`/workspace`
  只属于 Docker mount namespace，不进入 CommandPolicy。
- `completed` 不能由模型自报决定，Runtime 会从最终 Git 状态和验证证据重新判定。
- legacy `PatchActor` / `LLMPatchGenerator` 不在生产入口调用图中。

Provider 输出规范化与协议修复：

```text
raw ModelResponse.content
  -> normalize_model_output(raw)
       -> bare JSON object
       -> exact Markdown JSON fence
       -> structurally validated DeepSeek DSML
  -> _parse_model_output(..., call_id_prefix="step-n")
  -> ModelOutputEvidence(raw, dialect, canonical, error, model, tokens)
       -> Eval model_outputs.jsonl / Session private model_outputs.jsonl
  -> valid only: compact canonical assistant JSON into conversation
  -> invalid only: protocol-repair user message; raw never enters conversation
  -> Runtime-owned ToolCall(call_id="step-n-call-m", name, arguments)
  -> ToolRegistry.execute(...)
```

关键函数：

```python
normalize_model_output(raw_output: str) -> NormalizedModelOutput
_decode_dsml(text: str) -> dict[str, Any]
_escape_dsml_parameter_text(xml_text: str) -> str
_parse_model_output(raw_output: str, actual_tests_passed: bool | None, call_id_prefix: str) -> ParsedModelOutput
_protocol_repair_message(error: str, *, attempt: int, maximum: int) -> Message
```

协议修复不变量：

- 原始输出不被规范化结果覆盖，Eval/Session 可以复盘 provider 真正返回的内容。
- Markdown 只接受整个 response 是一个 fence；DSML 只接受一个 tool envelope。
- DSML 参数正文按 opaque data 处理，源码里的 `<`、`&` 不会被 XML parser 误伤。
- 混合 envelope、尾随 action、重复参数、畸形类型 fail-closed。
- protocol repair 最多连续两次，只反馈错误和 canonical schema；合法 action
  重置 streak，lifetime attempts 不清零；二者与代码 `repair_attempts` 分账并随 Session resume 持久化。

可见验证命令规范化链：

```text
suite template: {workspace}/tests/auth
  -> AgentEvalRunner._verification_argv(...)
  -> ["python", "-m", "pytest", "tests/auth", "-q"]
  -> model run_tests arguments
  -> normalize_verification_argv(...)
       /workspace/tests/auth -> tests/auth
       ./tests/auth           -> tests/auth
       /workspace/../etc      -> reject
  -> canonical allowlist comparison
  -> CommandRequest(argv=relative, cwd=host worktree path)
  -> CommandPolicy.evaluate(...)
  -> SandboxExecutionContext
  -> DockerCommandBuilder maps host workspace to /workspace
```

只读探索缓存：

```text
(tool_name, canonical_arguments, workspace_version)
  -> first call: execute + cache ToolResult
  -> first unchanged repeat: return cached observation
  -> second unchanged repeat: StopReason.NO_PROGRESS
  -> successful patch: workspace_version += 1, same read/search may execute again
```

主要函数：

```python
normalize_verification_argv(
    argv: tuple[str, ...] | list[str],
) -> tuple[str, ...]

normalize_verification_cwd(cwd: str) -> str

normalize_allowed_verification_commands(
    commands: tuple[tuple[str, ...], ...],
) -> tuple[tuple[str, ...], ...]

normalize_run_tests_action(
    tool_name: str,
    arguments: dict[str, Any],
) -> dict[str, Any]
```

无进展检测使用规范化后的 `run_tests` 参数，并把默认 `cwd="."`、
`timeout_seconds=120` 纳入指纹。同一 workspace version 下，容器绝对写法和
相对写法属于同一动作，即使中间穿插只读工具也不会重复执行；`apply_patch`
成功增加 workspace version 后，同一测试可以再次执行以验证 repair。

生产执行链：

```text
ToolRegistry.describe()
  -> ModelRequest.tools
  -> OpenAI-compatible {tools:[function schemas], max_tokens, thinking=disabled}
  -> choices[0].message.tool_calls
  -> ModelTurn(tool_calls, finish, usage, evidence)
  -> AgentLoop assigns runtime_call_id=step-n-call-m

       apply_patch -> SafeExecutionService.execute_patch()
       run_tests   -> SafeExecutionService.execute_command()
  -> ToolResult(runtime_call_id, provider_call_id)
  -> durable Message(role=tool, tool_call_id=runtime, provider_call_id=opaque)
  -> Provider adapter serializes role=tool/tool_call_id=provider_call_id
  -> next ModelRequest
```

优先级：

```text
1. ModelTurn native tool_calls
2. provider/native structured final（当前 Provider 支持时）
3. textual JSON / fenced JSON / DSML fallback codec
4. bounded protocol repair
5. fail closed
```

finish 分类：

```text
tool_calls                         -> valid native action turn
stop                               -> final or textual fallback
length                             -> output_truncated, no parser/backend
insufficient_system_resource       -> bounded retryable provider failure
content_filter                     -> non-retryable content_filtered
empty content + empty tool_calls   -> bounded retry, then incomplete_provider_turn
malformed native arguments         -> invalid_tool_call, backend invocation 0
```

预算不变量：

```text
context_budget == max_input_tokens
max_input_tokens
  <= model_context_window - max_output_tokens - safety_headroom_tokens
```

Adapter 在 HTTP 前估算完整 UTF-8 serialized messages、message structure 和
tools，而不是只加 `message.content` 字符数。Structured compaction 可以压缩
initial system/user snapshot，并把 native assistant call 与对应 tool results
作为原子 group。raw Provider evidence 不进入 compacted model conversation。

兼容层：旧 `complete(messages)` fake、planner 和文本 provider 仍可被
AgentLoop 适配成 textual `ModelTurn`；`codeteam.agent.protocol` 未删除。生产
OpenAI-compatible client 实现 `turn(ModelRequest)`，CLI run 与 Agent Eval 继续
共享同一个 `CodingAgentRuntime`。

### 15. Verification Environment Contract

这一层不属于 `VerificationService` 的 task correctness 判断，也不扩展旧
Orchestrator RecoveryPolicy。它是 Runtime 调用 Provider 前的独立环境门：

```text
CodingAgentRuntime.run(request)
  -> DockerSandboxPreflight.check(workspace)
       argv=("test", "-d", "/workspace")
       answers: can the container start with this mount?
  -> VerificationEnvironmentRequirement.from_commands(
       task_verification_commands or verification_commands
     )
  -> DockerVerificationEnvironmentPreflight.check(workspace, requirement)
       profile.image == run_tests profile.image
       fixed argv=("python", "--version")
       fixed argv=("python", "-m", "pytest", "--version")
       DockerImageInspector -> image ID / RepoDigest when available
       answers: can required Python verification start?
  -> Provider / AgentLoop
  -> run_tests
       normalize argv/cwd
       exact visible allowlist
       SafeExecutionService.execute_command(
         SafeCommandExecutionRequest(sandbox_profile=same profile)
       )
       CommandPolicy -> DockerRunner
       -> exit 0: passed
       -> pytest assertion exit 1: test_failed, Agent-visible repair evidence
       -> No module named pytest: verification_environment_failed, terminal pause
```

关键模型：

```python
VerificationEnvironmentRequirement(
    capabilities=(PYTHON, PYTEST),
    required_commands=(...),
    unsupported_commands=(...),
)

VerificationEnvironmentCheckResult(
    available: bool,
    category: str,
    metadata=VerificationEnvironmentMetadata(
        configured_image,
        image_id,
        image_digest,
        python_version,
        pytest_version,
        probe_argv,
        capabilities,
    ),
)
```

当前 requirement detector 故意只接受 authoritative workspace-relative
`python -m pytest ...`。没有 command 的产品 run 仍按当前 Python Runtime 默认
contract 探测 Python+pytest。它不是通用 LanguageRuntimeManager；不识别的
authoritative command 会 `unsupported_verification_contract` fail closed。

Runtime 与 Grader 的物理执行不同：

```text
Runtime: configured Docker image, executable "python"
Grader:  trusted host, project .venv/bin/python
```

两者不强行共享 host `.venv`。Eval manifest 的 `verification_contract` 记录共同
logical capabilities，以及 Runtime image/Python/pytest 和 Grader Python/pytest
版本；`preflight_results` 同时保留旧 sandbox 字段和新 verification metadata。

镜像构建边界：

```text
docker/sandbox/Dockerfile
  FROM python:3.11.15-slim-bookworm@sha256:<pinned>
docker/sandbox/requirements.txt
  pytest==9.1.1 + exact direct runtime dependencies
docker/sandbox/.dockerignore
  context only Dockerfile + requirements
```

构建命令：

```bash
docker build -t codeteam-sandbox:latest -f docker/sandbox/Dockerfile docker/sandbox
```

安全边界保持：preflight probe 是不可由 Agent 控制的 fixed infrastructure argv，
所以可直接使用注入的 DockerRunner；Agent `run_tests` 仍必须经过 exact allowlist、
CommandPolicy 和 SafeExecutionService。没有 mount host `.venv`，没有 Runtime
`pip install`，没有放宽 not-ready repeated-action threshold；新的 completion
handshake 见下一节。

### 16. Verification Scratch Isolation 与 Versioned Completion

第三轮把执行闭环补成以下状态链：

```text
Model native tool call
  -> RuntimeToolRegistry
  -> apply_patch (host SafeExecutionService)
       -> workspace_version += 1
  -> run_tests
       -> /workspace readonly
       -> bounded /tmp tmpfs
       -> fingerprint before/after (no symlink following)
       -> VerificationEvidence(workspace_version)
  -> git_diff
       -> git_diff_checked_version = workspace_version
  -> CompletionGate.evaluate(current facts)
       -> not ready: structured missing requirements
       -> ready: model calls submit_result alone
  -> correlated role=tool result persisted
  -> typed Runtime terminal completion
```

#### Sandbox / Git hygiene 边界

`SandboxProfile.tmpfs_mb` 是 Runtime-owned、正数且最大 1024 MiB；默认 128 MiB。
`DockerCommandBuilder` 添加 `/tmp` tmpfs 和固定 scratch env。只有
Agent-visible verification 强制 `workspace_write=False`，preflight 继续使用同一
read-only profile，patch 不进入容器。

`GitWorkspace.content_fingerprint()` 用 `git ls-files --cached --others
--exclude-standard` 确定管理集合。普通文件 hash 类型、mode、bytes；symlink hash
link mode 与 `readlink` 文本；missing path 也是状态。它不扫描 ignored artifact，
不跟随 symlink，不自动清理。`render_workspace_diff` 同样跳过 untracked symlink。

#### Evidence / Completion 边界

`RuntimeEvidence` 现在同时保存 task commands、broad regression commands、完整
verification history、workspace fingerprint、hygiene、diff checked version 和
accepted submission。一次 patch 或 verification mutation 都改变版本并使旧证据
失效。验证 history 不清空，`tests_passed` 只聚合当前版本 required commands。

`CompletionGate` 是 provider/loop 无关的 pure policy。它不信模型的
`tests_passed/status/diff`，也不读取 hidden oracle。`submit_result` 只是请求：tool
closure 调 gate；AgentLoop 负责 sole-call 原子性、tool-result pairing 和独立 terminal
signal。现有 pause halt signal 只负责 execution/environment/hygiene，不承载完成。

#### Session / Evaluation 边界

`AgentRuntimeState` 持久化 evidence history、fingerprint、workspace version、diff
review version 和 hygiene。Resume 首先重算 fingerprint：相等才恢复 current-version
证据；不同或缺失则推进 version，旧证据保留但不能 ready。没有 durable ready bool。

Eval 仍保持 Actor 与 Grader 分离。新增指标只描述 Actor 控制面：
`actor_completed_count`、`within_budget_count`、`failure_category_counts`、
`completion_ready_count`、`completion_ready_but_actor_failed_count`、
`post_ready_tool_call_count` 和 `verification_workspace_mutation_count`。Grader 不会
因 hidden/acceptance 通过而救活 failed Actor。

### 17. Progress Control 与 Diagnostic Affordance

第四轮在不改 completion、repair、retrieval 和 sandbox scratch 所有权的前提下，
为统一 Runtime 增加三条正交链路：

```text
normal ModelRequest
  -> ProgressTracker(turn-based)
       -> 40% advisory level 1 (same request)
       -> 70% advisory level 2 (same request)
       -> 85% no source progress + not ready
            -> PAUSED / no_source_progress

inspect_environment(module | executable)
  -> strict Pydantic schema
  -> Runtime-owned fixed non-importing probe
  -> read-only verification Docker profile
  -> runtime_available + declared_by_project + portability warning

ContextBuildReport
  -> InitialContextSnapshot before serialization
  -> full current file + still visible: compact reference
  -> full current file + compacted away: cached full content
  -> partial/compressed/version drift: real read_file
```

`ProgressTracker` 在 `codeteam/agent/progress.py`，不把 checkpoint policy 分散进
`agent_loop.py`。Loop 只提供两个 provider-neutral extension point：在当前正常请求中
附加 advisory，以及在每个 tool result 后报告事实。批量 tool calls 不增加 step；
advisory 本身也不增加 Provider call。

`inspect_environment` 不走 Agent command allowlist，因为它不是 Agent-authored command；
与 preflight 相同，实际 argv/code 完全由 Runtime 固定并直接进入 Docker boundary。
这不改变 `run_tests -> CommandPolicy -> SafeExecutionService`，模型提供的 `python -c`
仍被拒绝。

新的 Session schema v4 只持久化累计 progress observability；resume 恢复 workspace
version 和累计指标，但可重建当前进程 advisory streak，避免持久化派生判断。

Eval result/summary 贯通 first patch、pre-edit、advisory、pause、environment inspection、
initial-context hit 和 source/diagnostic progress 指标。`scripts/run_single_agent_stability_validation.sh`
只为用户执行真实 Provider campaign；coder 仅执行 `--dry-run`。

### 18. Finalization-aware Budget 与 Terminal Settlement

第五轮没有提高 `max_steps`，而是把 budget 生命周期显式化：

```text
task declared budget + run cap
  -> effective_max_steps = min(task, cap)
  -> FinalizationBudgetPolicy
       -> reserve = max(3, ceil(effective * 20%))
       -> real diff + remaining <= reserve
            -> finalization advisory in the next normal ModelRequest
  -> CompletionGate before every tool call
       -> submit_result: Runtime-authorized completion
       -> apply_patch: legal reopen, evidence becomes stale
       -> redundant test/status/diff: skip with READY advisory
  -> step boundary
       -> safety halt first
       -> READY + fresh fingerprint match: Runtime settlement
       -> otherwise MAX_STEPS or typed pause
```

`codeteam/agent/finalization.py` 只拥有预算算术和 reserve entry 事实；它不能读取
grader 或决定 correctness。`CompletionGate` 核心未改，`agent_loop.py` 只在现有 step
boundary 增加 settlement hook，并在 batched calls 的每次调用前重算 gate。
`codeteam/agent/runtime.py` 组合 gate、fingerprint、advisory 和 bounded fallback summary。

`completion_mode` 区分 `model_submitted` 与
`runtime_budget_boundary_settlement`，并进入 Session schema v5、TURN event、Eval result/
summary/manifest。Eval 同时记录 task-declared、run-cap、effective budget 和来源；稳定性
脚本固定显式 run cap 20，并把 grader-correct/actor-failed、ready/actor-failed、Provider、
environment、protocol、workspace mutation 和非 20 effective budget 全部作为失败控制项。

Terminal settlement 没有额外模型调用，不运行 hidden grader，也不放松 current-version
verification/diff review。fresh fingerprint mismatch 说明 Runtime 观察之外发生 mutation，
此时 fail closed 为 `workspace_drift`。完整权衡见
[DD-W4-D7-14](../docs/design_decisions/DD-W4-D7-14.md)。

### 19. Batch-aware Stall Detection

第六轮把 legacy mechanical guard 的决策粒度从单个 ToolCall 修正为完整 Model Turn：

```text
ModelTurn(tool_calls=[...])
  -> declared_tool_calls += batch size
  -> for each call
       -> per-call completion/safety/budget check
       -> cached/repeated exploration: correlated skip observation
       -> fresh safe call: ToolRegistry / SafeExecution
       -> safety or budget halt: reject remaining calls with reason
  -> aggregate safe batch
       -> any fresh observation/source patch: stall streak = 0
       -> all cached/repeated: stall streak += 1 (at most once per turn)
       -> second complete stalled turn: typed stop
```

`AgentLoopState.cached_no_progress_count` 保留字段以兼容现有控制流，但语义现在是
“连续完整 mechanical stalled turns”，不再是“本 turn 内 cache hit 数量”。`read/search/
list/inspect`、cacheable status/diff 和等价 `run_tests` 可跳过重复执行并继续 batch；
`apply_patch`、`submit_result` 的 destructive/control invariant 不放宽，mixed submit
仍整批拒绝。

ProgressTracker 的职责没有变化：fresh diagnostic observation 可以让本 assistant turn
不属于 pure mechanical stall，但不会重置 source-progress clock；只有成功 patch 推进
workspace version/source progress。40%/70%/85% policy threshold、CompletionGate、
FinalizationBudget、TerminalSettlement、Sandbox 与 native provider contract 全部冻结。

AgentLoopResult 新增结构化 `failure_origin`，区分 cached batch、empty tool batch、empty
model turn、completion guidance ignored 和 repeated stall。批次计数定义如下：

```text
declared: provider-valid batch 中声明的调用
processed: 已获得 terminal Runtime disposition/ToolResult 的调用（包含 rejection）
rejected: backend 执行前被拒绝的 processed 子集
unprocessed-safe: 因 safety/budget rejection 未调用 backend 的已知非 completion 调用
```

这些字段进入 Runtime、Eval task result、summary、manifest 与 stability 聚合。稳定性 gate
不禁止合法 mechanical stop，而是要求 `batch_premature_stop_count == 0` 且
`progress_guard_unprocessed_safe_tool_call_count == 0`。完整权衡见
[DD-W4-D7-15](../docs/design_decisions/DD-W4-D7-15.md)，真实失败见
[FC-W4-D7-07](../docs/failure_cases/FC-W4-D7-07.md)。
