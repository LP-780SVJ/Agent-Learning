# CodeTeam 代码架构

本文档是持续维护的架构说明，记录当前代码如何分层、每层负责什么、哪些边界不能穿透。

## 当前定位

CodeTeam 是一个本地优先、provider-neutral 的 coding agent runtime 学习项目。它目前已经具备：

- Agent loop、工具调用、最终输出语义校验、事件和用量统计。
- 仓库扫描、符号索引、ImportGraph、检索排序、Repo Map、上下文压缩。
- Git patch/worktree/checkpoint/diff/rollback。
- CommandPolicy、Approval、SafeExecutor、Docker sandbox。
- Task/Plan/Repair/Failure Recovery。
- Durable Session、pause/resume、event log。
- CLI 产品入口：`run`、`resume`、`diff`、`rollback`、`inspect-repo`、`context`、`eval`。
- 检索 benchmark 和 Week4 任务评估设计。

## 关键边界

### CLI 层

CLI 只负责参数解析、请求 DTO、错误渲染和退出码。它不应该直接实现仓库检索、session 恢复、Docker policy 或 patch 逻辑。

### Application / Service 层

这一层编排多个 domain 模块。例如 `build_context.py` 把 RepositoryIndex、QueryAnalyzer、CandidateGenerator、FileRanker、RepoMap、InstructionLoader 和 Compressor 串起来。

### Agent Orchestrator

`SingleAgentOrchestrator` 负责状态推进和依赖编排，不应该实现底层 Git、Docker、LLM HTTP 或文件解析细节。

### Git 层

Git 层负责 workspace 状态和可恢复性：

- PatchValidator 先校验再应用。
- GitWorkspace 失败时验证没有半截副作用。
- WorktreeManager 做任务级隔离。
- CheckpointManager 做快速恢复。

### Execution / Sandbox 层

执行链路必须保持：

```text
CommandRequest -> CommandPolicy -> Approval -> SafeExecutor -> SandboxRunner
```

Policy 判断意图，Sandbox 限制能力。两者不能互相替代。

### Session 层

`session.json` 是 resume source of truth；`events.jsonl` 是 audit/debug/evaluation history。Session 不持久化 runtime object，只保存可重建配置和 durable state。

### Evaluation 层

Evaluation 是外部 judge，不应相信 agent final message。正式 task success 必须由 hidden acceptance、regression、安全和预算共同决定。

## 当前测试证据

最新收尾复验：

```text
普通 sandbox: 1192 passed, 6 skipped
提升权限终端: 1198 passed
```

主要测试目录：

- `tests/git/`: patch、worktree、checkpoint、diff、path security。
- `tests/execution/`: command policy、approval、safe executor、output limiter。
- `tests/sandbox/`: Docker command builder 和真实容器边界。
- `tests/session/`: durable session、event log、pause/reconcile/resume。
- `tests/cli/`: CLI layer1、integration、subprocess E2E。
- `tests/context/`, `tests/search/`, `tests/ranking/`, `tests/repomap/`: context engine。
- `tests/agent/`, `tests/repair/`, `tests/failures/`: orchestrator、repair、failure recovery。

## 已知架构缺口

- `codeteam run` 目前仍是产品化外壳，使用 `MockPlanner`，还不是完整真实 patch actor。
- 15-task hidden-oracle EvalRunner/Grader 尚未实现。
- Full mypy 存在历史 import-chain/stub/type debt。
- Full ruff 存在历史 style/lint debt，适合单独 cleanup 分支处理。
- Medium repo 暴露出 business behavior 和 cross-module retrieval 仍弱。

## 后续维护规则

- 新功能先明确所属层级，避免 CLI 或 orchestrator 吞掉底层职责。
- 新的安全能力必须同时说明 policy 边界和 sandbox 边界。
- 新的 agent 成功率必须来自外部 eval harness，不来自 agent 自我报告。
- 新 benchmark 必须保存 dataset、manifest、raw results 和 report。
- 大规模 lint/type cleanup 与功能修复分开提交，避免 review 噪声。
